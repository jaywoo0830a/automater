Chapter 1

설계 원칙과 프론트엔드 규약

#원칙프론트엔드에 미치는 영향
1Billboard URL/api/v1 하나만 하드코딩. 나머지는 _links에서 읽는다.
2하이퍼미디어버튼의 href와 method를 응답의 _links에서 가져온다.
3전이 후 전체 교체PUT/DELETE 응답을 setState(response)로 교체한다. 로컬 패치 없음.
4내부 ID 비노출숫자 PK 없음. slug 또는 값으로 식별한다.
5Collection Trap 방지한 화면 = GET 1번. 여러 엔드포인트 JOIN 불필요.

에러 처리

// 모든 에러 응답 (RFC 9457 Problem Details)
{
    "type": "validation_error",
    "title": "입력 검증 실패",
    "detail": "키워드 그룹 'region'이 존재하지 않습니다.",
    "suggestion": "키워드를 먼저 임포트하세요."
}
// → detail을 사용자에게 표시, suggestion은 작은 글씨로
// → HTTP 코드는 사용자에게 절대 보여주지 않음

Chapter 6

TitleWorkbench — 제목 구성 화면

이 화면은 SPA의 핵심이다. 키워드, 장식 풀, 띄어쓰기 스타일, 타이틀 블록을 한 화면에서 구성하고, 실시간 미리보기로 결과를 확인한 후, 캠페인으로 확정한다.

기대 UI: 제목 구성 (위→아래 4영역)
① 키워드 영역
[엑셀 업로드] 버튼 · 키워드 그룹별 접이식 패널
각 그룹 헤더: "지역 (3)" [이름변경] [삭제]
그룹 안: 키워드 칩 목록, 각 칩에 × 삭제, 접사 토글 스위치
칩 예: [강남동 ✕] 접사: 동 [ON→OFF] → 미리보기 "강남"
그룹 하단: 키워드 추가 인라인 입력

② 장식 풀 영역
[엑셀 업로드] 버튼 · 풀별 접이식 패널 (salt_prefix, salt_suffix 등)
각 풀: 항목 칩 목록, ON/OFF 토글, × 삭제, 추가 입력

③ 띄어쓰기 영역
스타일 행 목록. 각 행: 이름 입력 + 슬러그별 토글(공백/붙임)
[+ 스타일 추가] 버튼
시각 예: region[공백] subject[붙임] salt_suffix[공백] → "강남 수학추천"

④ 타이틀 블록 + 미리보기 영역
드래그 가능한 블록 배치: [keyword:region] [text:과외] [keyword:subject] [decoration:salt_suffix]
[+ 블록 추가] 버튼 (keyword/text/decoration 선택)
하단: [미리보기] 버튼 → 스타일별 샘플 제목 표시
맨 아래: [캠페인 생성] 버튼 → Campaign으로 전이
