Automater API Guide — Frontend Integration

이 문서는 openapi.yaml (OpenAPI 3.2.0)과 함께 프론트엔드 팀에 전달됩니다.
목적: 각 SPA 화면에서 어떤 API를 어떤 순서로 호출하는지 시각적으로 설명합니다.

Base URL: /api/v2
인증: 모든 요청에 Authorization: Bearer {token} 헤더 필요 (auth 제외)

2. 핵심 워크플로우 — Sequence Diagram

2.1 회원가입 → 첫 캠페인 생성

sequenceDiagram
    actor User
    participant SPA
    participant API

    User->>SPA: 회원가입 폼 작성
    SPA->>API: POST /auth/register
    API-->>SPA: {access_token, user}
    SPA->>SPA: 토큰 저장 (localStorage)

    User->>SPA: "캠페인 만들기" 클릭
    SPA->>API: GET /platforms
    API-->>SPA: [{id:1, name:"Naver Blog", ...}]
    SPA->>SPA: 플랫폼 드롭다운 렌더링

    User->>SPA: 이름 입력 + 플랫폼 선택
    SPA->>API: POST /campaigns {name, platform_id}
    API-->>SPA: {id:42, name:"내 캠페인", ...}
    SPA->>SPA: /campaigns/42 로 라우팅

2.2 민지의 엑셀 임포트 → 조합 생성

민지는 slug가 뭔지 모릅니다. 엑셀 컬럼 헤더가 "지역", "과목" 같은 한글이고, 시스템이 KeywordCategory.name 매칭으로 자동 해석합니다.

2.3 엑셀 재업로드 (키워드 추가/제거)

민지가 엑셀을 수정해서 다시 올리면, stale 조합이 자동 정리되고 새 조합만 추가됩니다. 이미 발송된 조합은 절대 삭제되지 않습니다.

2.5 토큰 편집기 — 타이틀 템플릿 구성

title_template 문자열은 DB에 저장되지 않습니다. 토큰 순서에서 자동 파생됩니다. 프론트엔드는 토큰 목록의 순서를 시각적으로 보여주고, 드래그로 재정렬할 수 있습니다. 
sequenceDiagram

    participant SPA
    participant API

    User->>SPA: 캠페인 상세 페이지 진입
    SPA->>API: GET /campaigns/42/tokens
    API-->>SPA: [{slug:"region",type:"keyword"}, {slug:"subject",type:"keyword"}, {slug:"salt_suffix",type:"pool"}]
    SPA->>SPA: 파생 템플릿 표시: "{region} {subject} {salt_suffix}"

    User->>SPA: "전문" 리터럴 토큰 추가

{slug:"_lit_expert", token_type:"literal", value:"전문"}
    API-->>SPA: {id:99, slug:"_lit_expert", ...}

    User->>SPA: 토큰 드래그로 재정렬
    SPA->>API: PUT /campaigns/42/tokens/reorder
{token_ids:[10, 99, 11, 12]}
    API-->>SPA: [{slug:"region"}, {slug:"_lit_expert"}, {slug:"subject"}, {slug:"salt_suffix"}]
    SPA->>SPA: 파생 템플릿 갱신: "{region} 전문 {subject} {salt_suffix}"

5. 프론트엔드 구현 가이드

5.1 두 가지 조합 생성 경로

프론트엔드는 사용자 유형에 따라 두 경로를 제공해야 합니다:

경로대상APIUI
벌크 임포트 민지 (비기술) /import/excel → /import/generate 엑셀 업로드 → 버튼 한 번
수동 구성 운영자 (기술) 토큰 편집 → picks 설정 → /combinations/generate 토큰 에디터 + 키워드 체크박스

5.2 파생 템플릿 표시 규칙

derived_template은 서버가 토큰 순서에서 자동 계산합니다. 프론트엔드도 동일한 규칙으로 로컬에서 미리보기를 렌더링할 수 있습니다: 

// Client-side template derivation
function deriveTemplate(tokens) {
  return tokens
    .sort((a, b) => a.sort_order - b.sort_order)
    .map(t => t.token_type === 'literal' ? t.value : `{${t.slug}}`)
    .join(' ');
}

5.3 리셋 버튼 UI 가이드

버튼동작확인 다이얼로그
소프트 리셋 미발송 조합만 삭제 "발송되지 않은 조합 N개가 삭제됩니다. 발송 이력은 보존됩니다."
하드 리셋 토큰/픽/조합 전부 삭제 "캠페인 설정이 초기화됩니다. 발송 이력만 보존됩니다. 이 작업은 되돌릴 수 없습니다."

5.4 배치 모니터링 폴링

배치가 pending 또는 running 상태일 때 GET /campaigns/{id}/batches/{bid}를 5초 간격으로 폴링합니다. completed 또는 failed가 되면 폴링을 중단합니다.
